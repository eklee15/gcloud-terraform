# Terraform Toy Example

This is a basic Terraform example that creates a VPC network on Google Cloud Platform (GCP).

## Prerequisites

- [Terraform](https://www.terraform.io/downloads) installed
- GCP credentials configured (either via `gcloud auth application-default login` or a service account key)
- A GCP project with the Compute Engine API enabled

## Basic Terraform Commands

### 1. `terraform init`

Initializes the Terraform working directory by downloading and installing the required providers and modules.

```bash
terraform init
```

**When to run:** Run this first, before any other Terraform commands. Also run it when you add new providers or modules.

**What it does:**
- Downloads the Google provider plugin
- Creates a `.terraform` directory with provider binaries
- Generates `.terraform.lock.hcl` to lock provider versions

---

### 2. `terraform validate`

Checks that your Terraform configuration is syntactically correct and has valid resource definitions.

```bash
terraform validate
```

**When to run:** After creating or modifying `.tf` files to catch configuration errors early.

**What it does:**
- Validates the syntax of all `.tf` files
- Checks that resource types and arguments are valid
- Does NOT validate that resources can actually be created (no API calls)

---

### 3. `terraform fmt`

Formats your Terraform configuration files to follow standard style conventions.

```bash
terraform fmt
```

**When to run:** Before committing code to maintain consistent formatting across the project.

**What it does:**
- Reformats all `.tf` files with consistent indentation and spacing
- Makes code more readable and maintainable

**Options:**
- `terraform fmt -recursive` — formats all `.tf` files in subdirectories
- `terraform fmt -check` — checks formatting without modifying files

---

### 4. `terraform plan`

Creates an execution plan showing what changes Terraform will make to your infrastructure.

```bash
terraform plan
```

**When to run:** Before applying changes to see exactly what will be created, modified, or destroyed.

**What it does:**
- Compares your `.tf` files with the current state
- Shows all resources that will be added, changed, or removed
- Does NOT make any actual changes to your infrastructure

**Save the plan to a file (recommended):**
```bash
terraform plan -out=tfplan
```

**Useful options:**
- `terraform plan -var="key=value"` — pass variable values
- `terraform plan -destroy` — plan to destroy all resources

---

### 5. `terraform apply`

Applies the Terraform configuration to create, update, or delete resources in your GCP environment.

```bash
terraform apply
```

**When to run:** After reviewing the plan and confirming you want to make the changes.

**What it does:**
- Creates or modifies resources defined in your `.tf` files
- Updates `terraform.tfstate` with the new resource state
- Prompts for confirmation before making changes

**Apply a saved plan (recommended):**
```bash
terraform apply tfplan
```

**Skip confirmation (use with caution):**
```bash
terraform apply -auto-approve
```

---

### 6. `terraform output`

Displays outputs defined in your Terraform configuration.

```bash
terraform output
```

**When to run:** After `terraform apply` to retrieve information about created resources (e.g., IP addresses, URLs).

**What it does:**
- Displays all outputs defined in your configuration
- Reads from `terraform.tfstate`

**Get a specific output:**
```bash
terraform output network_name
```

**Output as JSON:**
```bash
terraform output -json
```

---

## Quick Start Workflow

Here's the typical workflow for using Terraform:

```bash
# 1. Initialize the working directory
terraform init

# 2. Validate your configuration
terraform validate

# 3. Format your code (optional but recommended)
terraform fmt

# 4. Preview the changes
terraform plan -out=tfplan

# 5. Apply the changes (after reviewing the plan)
terraform apply tfplan

# 6. View outputs
terraform output

# 7. To clean up, destroy all resources
terraform destroy
```

## File Structure

- `main.tf` — The main Terraform configuration that defines resources and providers
- `.terraform/` — Directory containing downloaded provider plugins (generated by `terraform init`)
- `.terraform.lock.hcl` — Locks provider versions (committed to version control)
- `terraform.tfstate` — Current state of your infrastructure (DO NOT commit to version control)
- `terraform.tfstate.backup` — Backup of the previous state (DO NOT commit to version control)

## Current Example
